# Candidate Error Taxonomy

The error taxonomy exists to choose interventions, not to blame the candidate or generate vanity analytics.

## Canonical classes

| Code | Class | Meaning | Typical intervention |
|---|---|---|---|
| K | Knowledge | rule/concept not known | focused study / worked example |
| R | Retrieval | knew previously but could not retrieve | retrieval + spacing |
| I | Interpretation | misread stem/operator/text | reading/operator drills |
| C | Calculation | procedure/arithmetic error | worked practice / fluency |
| T | Trap | fell for distractor/bank transformation | contrast/trap drills |
| A | Attention | avoidable execution slip | execution protocol / pace |
| M | Metacognition | confidence/judgment mismatch | calibration feedback |
| TIME | Time | knowledge exists but time constraint caused failure | timed fluency/strategy |

A low-friction UI may initially expose fewer buttons and map them to these richer categories later.

## Multi-cause errors

One question can have more than one plausible cause. Preserve primary/secondary cause or uncertainty rather than forcing false certainty.

## Confidence interaction

Wrong + high confidence should raise the probability of knowledge/misconception/metacognition issues relative to random uncertainty. This is a diagnostic heuristic to validate empirically, not an automatic truth.

## Transversal patterns

If errors across subjects repeatedly involve negation, conditional logic, exceptions or absolutization, create/consider transversal skill evidence instead of treating each subject failure as independent.

## Data collection rule

Do not interrupt every answer with a long error form. Capture only enough information to materially improve intervention selection; deeper labeling can be proposed later from answer/context and confirmed when useful.
