# ADR 0009 — Batismo 2.0 and Masterclass Neurociência are core Learning OS inputs

**Status:** Accepted  
**Date:** 2026-09-01

## Context

The initial V0 documentation treated OQF/Batismo/Masterclass as a future knowledge-ingestion lane. After full recovery of the canonical material, this underrepresented their role: Batismo already defines a practical state machine for high-stakes exam preparation, while Masterclass defines readiness, attention, challenge, feedback, habit and progression controls.

The project is intended to improve study decisions, not merely host a question bank. These methods therefore affect the core product behavior.

## Decision

Promote the integrated Batismo 2.0 + Masterclass Neurociência doctrine to **first-class Learning Operating System design authority**.

Responsibilities:
- Batismo governs preparation phases, allocation, continuity, overload, specificity, urgency and simulation;
- Masterclass governs readiness, focus, task clarity, challenge-skill adjustment, feedback/progress, habit friction and recovery-aware execution;
- learning science validates/refines techniques and mechanisms;
- candidate telemetry personalizes and can override a default intervention when repeated local evidence warrants it;
- exam evidence determines target value and specificity.

M001 remains the data/assessment foundation, but must preserve telemetry/schema extension points needed by the Learning OS.

## Consequences

Positive:
- product decisions reflect the actual method intended to drive approval performance;
- learning techniques become operational rules rather than generic future notes;
- Decision Engine can eventually prescribe both **what** and **how** to study;
- candidate evidence can evaluate the method rather than relying on memory/anecdote.

Costs:
- additional session/context telemetry;
- phase/intervention versioning;
- more explicit distinction between practitioner outcome evidence and scientific mechanism evidence.

## Rejected alternatives

1. Keep Batismo/Masterclass as optional content/RAG only — rejected because it fails the product thesis.
2. Implement all Learning OS behavior inside M001 — rejected because trustworthy corpus/attempt data is still the necessary first dependency.
3. Replace practitioner doctrine entirely with generic learning-science advice — rejected because it would discard high-specificity exam preparation strategy and real-world method history.
