# Question Learning Packet

## Idea

A question can become a complete post-response learning object, but only when the candidate state justifies the depth.

```text
QUESTION
├── Identity / provenance
├── Official bank key
├── Decisive explanation
├── Authority/source basis
├── Alternative/distractor analysis
├── Trap pattern
├── Concept contrast
├── Knowledge map
├── Memory candidates
└── Candidate evidence / recommended intervention
```

## Adaptive explanation depth

Do not force every correctly answered question into a long lesson.

Suggested levels:

```text
correct + high confidence → depth 1
correct + low confidence  → depth 2
wrong + low confidence    → depth 3
wrong + high confidence   → depth 5
```

Additional factors can include prior errors, question importance and current mastery estimate.

## Distractor intelligence

Alternative-level labels may include:
- polarity inversion;
- changed deadline/value;
- rule vs exception;
- absolutization;
- competency/authority swap;
- similar concept substitution;
- partially true statement;
- outdated legal rule;
- fabricated condition/exception.

Later candidate analytics can identify cross-subject susceptibility such as repeated failures on exception/negation structures.

## Contrastive learning unit

When the failure is confusion between two concepts, the best packet may be a compact contrast rather than a generic explanation. Example structure:

```text
Delegation            Avocation
----------            ---------
no hierarchy required hierarchy required
rule/ordinary         exceptional
...
```

## Memory creation

A packet may propose a flashcard/memory item, but not every error should become a card. Some errors are better corrected by contrastive questions, worked application or source reading.

## Cost control

Deep packets are generated/on-demand for answered, high-value, repeated or problematic questions. The full corpus receives only lightweight canonical metadata until enrichment is useful.
