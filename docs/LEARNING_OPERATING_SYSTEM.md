# Learning Operating System — Batismo 2.0 + Masterclass Neurociência + Learning Science

## Status

**Canonical design authority for learning behavior.**

This document promotes the recovered Batismo 2.0 / Masterclass Neurociência corpus from a future knowledge source into the central learning operating system of Exam Intelligence.

The system is no longer modeled as only:

`exam data → question practice → metrics`.

It is modeled as:

```text
EXAM DEMAND
    ↓
CANDIDATE STATE
    ↓
BATISMO PHASE / STUDY STRATEGY
    ↓
MASTERCLASS READINESS + ATTENTION + DIFFICULTY GATES
    ↓
TECHNIQUE / INTERVENTION
    ↓
ACTIVE EXECUTION
    ↓
FEEDBACK + ERROR DIAGNOSIS
    ↓
DELAYED RETRIEVAL / TRANSFER
    ↓
CANDIDATE EVIDENCE
    ↓
RECALIBRATION
```

The purpose remains the product north star:

> **What should the candidate study now, for how long, using which intervention, under which conditions, and why?**

## 1. Four sources of intelligence

### 1.1 Exam Intelligence
Determines **what matters**:
- edital / Atomic Tree;
- weight and incidence;
- bank, role and organization similarity;
- exact recurrence, question-family recurrence and topic recurrence;
- scoring policy;
- days to exam;
- legal/content version.

### 1.2 Batismo Strategy Canon
Determines **which preparation state and allocation strategy applies**:
- material validation;
- basic formation `80/20`;
- basic formation `20/80`;
- mesocycle;
- imminent-edital / surprise-subject response;
- final 50-day sprint where applicable;
- 10-day countdown where applicable;
- full simulation;
- post-exam debrief.

These are operational states with entry/exit criteria, not biological laws or rigid calendar promises.

### 1.3 Masterclass Cognitive-Regulation Canon
Determines **how the session should be executed given current readiness and behavior**:
- one primary objective;
- alertness / fatigue / recovery constraints;
- task clarity;
- attention environment;
- challenge-skill match;
- active rather than passive work;
- fast informative feedback;
- visible proximal progress;
- habit / start-friction architecture;
- progressive variation;
- frustration / dropout protection.

### 1.4 Learning Science + Candidate Evidence
Determines **which parts are strongly supported, contextual, candidate-specific or in need of revision**.

The scientific lane refines the operational method. Candidate outcome evidence personalizes it.

The system must distinguish:

```text
method works in practice
≠
every proposed biological explanation is proven
```

A neuroscience mechanism can be incomplete while the behavioral protocol remains useful. Conversely, an elegant mechanism does not justify a study intervention without outcome evidence.

## 2. Evidence policy for Batismo / Masterclass

Batismo and Masterclass are not treated as disposable anecdotes. They are a **high-priority practitioner operating canon** because they are purpose-built for Brazilian high-stakes exams and are associated with a substantial history of reported approvals and successful candidates.

However, the repository must preserve distinct evidence questions:

1. **Practitioner outcome evidence** — did candidates using the program achieve relevant outcomes?
2. **Protocol evidence** — which concrete behaviors were repeatedly implemented?
3. **Candidate-local evidence** — does the intervention improve this candidate's delayed performance?
4. **Scientific intervention evidence** — does broader research support the technique?
5. **Mechanism evidence** — is the proposed neural/biological explanation established in a compatible population/task?

### Operational prior

Use the following default:

- **Batismo/Masterclass + convergent learning science + positive candidate data:** strongest default.
- **Batismo/Masterclass + reported outcome history + no scientific contradiction:** eligible default; measure locally.
- **Scientific support + no practitioner mapping:** eligible intervention; integrate conservatively.
- **Course mechanism disputed but behavioral protocol useful:** keep protocol, rewrite explanation.
- **Candidate data repeatedly contradicts expected benefit:** adapt or stop for that candidate.
- **Unsafe clinical/medical action:** never automate regardless of course claim.

The objective is not to police language for its own sake. It is to preserve the parts that produce performance and make the causal story more accurate over time.

## 4. Material validation comes before optimization

For each edital node:

1. locate the primary study source;
2. skim for scope and structure;
3. compare source coverage with real questions;
4. mark missing, excess, stale and duplicate material;
5. remove excess only with traceability;
6. escalate to law/book/video/teacher only where the current source is insufficient.

The system should represent:

```text
syllabus_node
→ source coverage
→ question evidence
→ source gap
→ selected material
```

A perfect scheduler cannot compensate for studying the wrong or incomplete source.

## 5. Basic formation — 80/20

Purpose: broad construction of the exam map and minimum usable conceptual models.

Canonical loop per topic:

```text
skim / overview
→ small diagnostic question sample
→ directed reading / explanation
→ active retrieval or new questions
→ record coverage + time + confusion
```

`80/20` describes dominant effort allocation (more acquisition/theory than questions), not a mandatory minute ratio.

Exit should depend on evidence such as:
- all target nodes touched or explicitly deferred;
- study source validated;
- basic question sample attempted;
- major unknown prerequisites identified;
- time/cost measured.

---

## 6. Basic formation — 20/80

Purpose: convert broad exposure into retrieval, application and error-driven repair.

```text
questions by Atomic Topic
→ answer before consultation
→ feedback
→ classify failure
→ return only to the exact missing rule/source
→ retrieve/apply again
→ update candidate state
```

This phase operationalizes one of the strongest convergences between Batismo and learning science: **attempt → feedback → targeted repair → re-attempt**.

The system must not interpret `20/80` as “do thousands of blind questions.” Question volume without diagnosis is low-value repetition.

---

## 7. D1…Dn and mesocycles

Rank disciplines/topics by both:

```text
candidate weakness
× exam importance / leverage
× prerequisite centrality
× opportunity to improve
```

The highest-priority target receives the strongest available cognitive window where practical. Other disciplines remain alive through maintenance/retrieval so the system does not create catastrophic forgetting by disappearing them for long periods.

Batismo's mesocycle logic becomes a dynamic allocation engine:

- approximately 40–50% of available study capacity may be concentrated on a differential target when the state supports it;
- other disciplines receive maintenance/retrieval work;
- the target can progress from acquisition-heavy to balanced to question-heavy work;
- rotate only after evidence-based review.

The course contains ambiguity about exact week count. Store phase template and actual candidate data separately.

## 8. Masterclass session gates

Before prescribing a heavy session, resolve in order:

```text
1. safety / official constraints
2. target and phase
3. biological readiness
4. task clarity
5. attention environment
6. skill-difficulty match
7. active-learning mode
8. feedback design
9. recovery requirement
10. telemetry / next decision
```

### Readiness
The system does not assume all available hours are cognitively equivalent.

Record optional, low-friction context:
- alertness;
- sleep quality / duration if voluntarily tracked;
- fatigue;
- unusual illness/shift context;
- time of day.

Low readiness should generally reduce cognitive demand or move difficult work to a better window rather than automatically increasing stimulant use or sacrificing sleep.

### Clarity
A session starts with a concrete output, e.g.:
- `20 unseen questions of Topic X`;
- `recover articles 12–15 without notes, then validate with 8 items`;
- `repair misconception Y and pass delayed retest`.

“Study administrative law” is not a sufficient task definition.

### Challenge-skill match
Use observable proxies rather than claiming to measure flow:
- accuracy;
- confidence;
- response time;
- omission;
- perceived difficulty;
- frustration;
- repeated error sequence;
- support used.

Rules:
- too hard → repair prerequisite / decompose / scaffold;
- too easy → reduce support / increase variation, speed or complexity;
- difficulty reasonable but attention low → fix clarity/environment/readiness;
- stable success with meaningful effort → progress.

## 9. Error is the routing signal

Minimum error taxonomy:
- `knowledge_gap`;
- `recall`;
- `misread`;
- `procedure`;
- `attention`;
- `time`;
- `source_gap`;
- `guess`;
- `trap_or_discrimination`;
- `confident_wrong` as a high-priority calibration state.

A wrong answer does not automatically trigger “more questions.”

Examples:

| State | Intervention |
|---|---|
| no model | focused theory + worked example + retrieval |
| recall failure | retrieval / spaced relearning |
| concept confusion | contrastive representation + mixed discrimination questions |
| procedure error | worked sequence then independent variants |
| source gap | repair material/source |
| bank trap | distractor/wording drills |
| slow but accurate | timed fluency |
| confident wrong | misconception correction + immediate contrast + delayed unseen validation |
| attention error | environment/reset/shorter active block |

## 10. Retrieval, spacing and feedback

The default learning loop is:

```text
attempt from memory
→ commit answer / prediction
→ corrective feedback
→ diagnose discrepancy
→ targeted restudy/elaboration
→ successful retrieval
→ later retrieval under variation
```

Key rules:
- test before rereading when the knowledge is expected to be retrievable;
- repeated passive exposure is not a mastery signal;
- use delayed performance, not only immediate fluency;
- schedule revisits adaptively rather than using a universal 7/14/21 calendar;
- mix related concepts when discrimination is the target;
- use elaboration and worked examples when retrieval alone cannot build the missing model;
- prefer unseen/equivalent questions for validation.

## 11. Habit and execution architecture

Study initiation should be engineered:

```text
stable cue/context
→ tiny first physical action
→ clear task
→ active work
→ feedback / visible progress
→ next action already defined
```

Track:
- start latency;
- session execution rate;
- focused minutes;
- distraction events;
- valid active output;
- next action defined.

The objective is reliable execution, not symbolic streaks. A lapse does not reset a magical biological clock.

## 12. OQF / 30-day behavioral rehearsal

Treat the 30-day protocol as a controlled field experiment, not an approval guarantee or universal habit-formation period.

### Preparation
- target exam and phase defined;
- baseline captured;
- sources/tools tested;
- schedule/recovery constraints known;
- minimum session defined.

### Days 1–21
- stable execution context;
- active practice from the start;
- progressive load only when execution/recovery tolerate it;
- one material change at a time when possible.

### Days 22–27
- increased exam specificity;
- timing/order/decision practice;
- realistic but safe pressure.

### Days 28–30
- comparable retest;
- compare baseline and delayed result;
- identify dominant errors;
- choose `maintain | adapt | replace | investigate`;
- define next mesocycle.

The protocol's success criterion is **better evidence and better performance decisions**, not merely “completed 30 days.”

---

## 13. Final stretch and exam specificity

As the exam approaches, increase similarity between practice and the real task:
- real bank item formats;
- timing;
- paper/answer-sheet constraints where relevant;
- subject switching;
- skipping/return decisions;
- blank/penalty strategy;
- full simulations;
- post-simulation autopsy.

The Batismo 50-day and 10-day structures are canonical templates that may be selected when compatible with the actual timeline and candidate state; they are not universal countdown laws.

---

## 14. What the Learning OS optimizes

Not:
- seated hours;
- number of highlighted pages;
- streak length;
- number of questions seen;
- immediate familiarity;
- “dopamine” as a proxy;
- exhaustion.

Optimize:
- weighted edital coverage;
- validated retrieval;
- delayed retention;
- application/transfer;
- exam-specific accuracy/score;
- response-time control;
- confidence calibration;
- error reduction;
- stable execution;
- recovery-compatible progress;
- expected score gain per unit of study time.

## 15. Implementation consequences

### M001
M001 remains a trustworthy data/assessment vertical slice. It must, however, preserve enough session context so future learning decisions can be reconstructed without schema surgery.

Minimum hooks:
- `study_phase_snapshot` (nullable/versioned);
- `session_goal`;
- `planned_minutes`;
- optional `alertness`, `task_clarity`, `perceived_difficulty`, `frustration`;
- `start_latency` / focused-time fields where available;
- intervention/technique ID/version when a session is prescribed later;
- next action / completion outcome.

Do **not** implement the full adaptive Learning OS inside M001.

### Immediately after the foundation
The highest-priority sequence is:
1. Atomic Tree / current edital mapping;
2. candidate state and Batismo phase inference;
3. session/readiness telemetry;
4. intervention registry from Batismo/Masterclass/science;
5. delayed validation / retention;
6. Decision Engine / Today;
7. richer Bank DNA, legal authority, semantic families and advanced modeling as justified.

The learning engine is now a first-class product capability, not a distant optional module.
