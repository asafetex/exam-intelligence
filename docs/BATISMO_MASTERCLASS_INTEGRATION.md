# Batismo 2.0 ↔ Masterclass Neurociência Integration

## Purpose

This document defines how the two recovered practitioner corpora control Exam Intelligence.

The source package used for this integration contains:
- **Batismo 2.0:** 11 transcript-derived lesson ingestions plus canonical rules, state machine, decision rules and conflict register;
- **Masterclass Neurociência:** 6 transcript-derived lessons, claims/technique registries and a separately audited 19-document scientific attachment pack;
- **OQF protocol:** behavioral rehearsal / 30-day measurement framework.

The public repository stores derived operational doctrine and source IDs, not paid transcripts or restricted full-text materials.

## 1. Division of responsibility

| Problem | Batismo | Masterclass | Exam Intelligence |
|---|---|---|---|
| What is the target? | primary concurso + edital | focus/exclusion | target exam model |
| What should be studied? | phase, D1…Dn, 80/20, 20/80 | challenge/readiness constraints | Atomic Tree + incidence + candidate gap |
| When should it be studied? | weekly/mesocycle/final strategy | alertness/recovery | schedule recommendation |
| How should it be studied? | reading/questions/error/simulation techniques | active attention, feedback, habit, progression | intervention protocol |
| How hard should it be? | overload/variability/specificity | challenge-skill regulation | adaptive difficulty |
| How is failure treated? | error classification + return to exact source | error as information, frustration control | diagnosis + intervention |
| How is progress judged? | coverage/execution/simulation | visible proximal feedback | delayed performance + metrics |
| How is the plan changed? | state transitions / mesocycle review | telemetry and adaptation | Decision Engine |

Canonical integration rule:

> **Batismo chooses the strategic state and study allocation; Masterclass regulates cognitive/behavioral execution; Exam Intelligence supplies exam evidence and candidate telemetry; learning science validates/refines the intervention and causal story.**

## 2. What is adopted as default operational doctrine

The following are first-class defaults unless current exam/candidate evidence gives a reason to override them:

1. one primary exam target;
2. validate edital/material before deep optimization;
3. build broad coverage before narrow perfection;
4. use questions early as diagnosis, not only final assessment;
5. shift toward question-dominant retrieval after initial formation;
6. return selectively to the exact source gap instead of rereading everything;
7. keep all relevant disciplines alive while concentrating extra capacity on the current differential target;
8. rank D1…Dn from real difficulty **and** exam leverage;
9. classify errors instead of treating all wrong answers alike;
10. use progressive overload, continuity, specificity, individuality and variability;
11. simulate the real bank/task progressively;
12. preserve recovery rather than buying hours with sleep deprivation;
13. design stable study-start cues and low-friction entry;
14. make progress visible at session/week/mesocycle level;
15. use telemetry to change the method instead of moralizing failure.

These rules are compatible with the central learning-science findings incorporated in `SCIENTIFIC_LEARNING_CANON.md`.

## 3. Batismo operational state machine

### `material_validation`
Goal: every target edital node maps to a sufficient source or an explicit gap.

### `basic_80_20`
Goal: broad first representation; acquisition dominant but questions are already used to orient attention.

### `basic_20_80`
Goal: retrieval/application dominant; theory becomes targeted repair.

### `mesocycle`
Goal: concentrate extra effort on a high-leverage weak target while maintaining the rest.

### `edital_imminent`
Goal: accelerate coverage/priority when a material official event changes urgency.

### `surprise_subject`
Goal: reverse-engineer a newly introduced subject through real questions + vocabulary/concepts + accelerated broad coverage.

### `final_sprint_50`
Goal: template for a high-specificity final block when approximately compatible with actual time and state.

### `countdown_10`
Goal: template for last-stage diagnosis, proportional sets, correction, error retesting and full-condition simulation.

### `simulation`
Goal: reproduce the scoring/decision/task environment closely enough to expose execution risk.

### `post_exam`
Goal: preserve outcome evidence and update the model.

Exact week/day values from the corpus are stored as templates/examples. Exit criteria are evidence-driven.

## 4. Masterclass cognitive regulation

### Focus is exclusion
A declared target should change resource allocation. A candidate cannot call every attractive exam “secondary but still priority.”

System behavior:
- one primary target;
- secondary targets labeled compatible, opportunistic or distracting;
- recommendations optimize against primary target first.

### Readiness is a real constraint
The candidate's hours are not interchangeable.

System behavior:
- difficult D1 work is preferentially placed in the best observed window;
- low alertness can downgrade task complexity;
- sleep deprivation never automatically produces a “study harder” response;
- recovery is a planning input, not a moral judgment.

### Challenge must track skill
The system does not claim to measure neural flow. It tracks conditions that make productive absorption more likely.

Observed signals:
- accuracy;
- confidence;
- latency;
- omissions;
- support required;
- perceived difficulty;
- frustration;
- attention failures.

### Feedback must be informative
The pedagogical unit is:

`attempt → result → explanation/diagnosis → correction → new attempt`.

A green/red animation is not useful feedback by itself.

### Visible progress sustains the long goal
Show real proximal evidence:
- edital nodes covered;
- unique questions validated;
- error category reduced;
- delayed retests passed;
- response time improved;
- mock score improved;
- adherence to the planned protocol.

Do not manufacture progress from vanity counters.

### Habit is entry automation, not mindless study
The aim is to automate the transition into deliberate work:
- stable context/cue;
- material prepared;
- next action known;
- minimum safe version for difficult days;
- easy recovery after lapses.

## 5. Technique matrix recovered from the corpus

### Acquisition
Preferred:
- optimized/direct reading;
- skimming for structure;
- scanning/deeper reading targeted by questions;
- worked examples where a mental model is absent;
- short explanation/video when it repairs a documented ambiguity or prerequisite.

Not default:
- long transcription-style summaries;
- beautiful notes as a proxy for learning;
- passive video consumption without prediction/retrieval/application.

### Retrieval/application
Preferred:
- questions before consultation;
- free recall / explain from memory;
- re-attempt after targeted repair;
- mixed discrimination among similar rules;
- exam-specific practice.

### Error material
Preferred:
- record **cause + corrective action + source locator**;
- temporary contrast/ficha/mnemonic when a recurring atomic confusion justifies it;
- generate a flashcard only when the target is truly atomic/retrieval-based.

Not default:
- copying every wrong question into a notebook;
- creating permanent notes for every error.

### Review
Preferred:
- performance-triggered retrieval;
- adaptive spacing;
- successive relearning;
- retest using unseen/equivalent items.

Not default:
- universal fixed 7/14/21 rereading calendar;
- reviewing only because a date arrived despite strong/weak evidence being ignored.

### Simulation
Progress from partial specificity to full exam conditions:
- item format;
- bank wording;
- timing;
- subject switching;
- scoring/blank strategy;
- answer sheet / physical constraints when relevant;
- full post-test autopsy.

## 6. Error-to-intervention routing

| Failure | Default response |
|---|---|
| did not know concept | focused source repair + worked example + retrieval |
| forgot known concept | retrieval + adaptive spaced retest |
| confused adjacent concepts | contrast table/map + discrimination items |
| procedural/calculation error | step trace + guided example + variants |
| misread negative/exception | command/operator drill + slower deliberate parse then speed |
| attention/marcare | environment/reset + shorter active unit + capture interruption |
| source insufficient | replace/escalate source |
| too slow | timed fluency after correctness exists |
| bank distractor | trap-pattern drill |
| confident wrong | high priority misconception repair + delayed unseen validation |
| blind guess | knowledge state remains uncertain; do not count as mastery |

## 7. OQF as experimental operating cycle

OQF is treated as a **behavior/performance field experiment**.

Required components:
- baseline;
- target behavior;
- stable cue/context;
- minimum version;
- normal version;
- progression ceiling;
- active output metric;
- performance metric;
- recovery context;
- end-of-window decision.

The 30-day window is useful as a review cycle because it produces repeated observations. It is not encoded as a universal neural/habit deadline.

A protocol can be judged successful even if the final score does not immediately jump when it produced reliable diagnostic data that leads to a better next cycle. Long-term success, however, still requires transfer to exam performance.

## 8. Practitioner outcome evidence is first-class

The project must not commit the opposite error of treating a mature exam-preparation method as worthless because not every component has an RCT.

Add a separate evidence type:

`practitioner_outcome_evidence`

Possible records:
- cohort/date;
- target exam;
- participant count when documented;
- completion/exposure definition;
- approvals/classifications/TAF or other relevant outcomes;
- source of outcome claim;
- selection/attrition limitations;
- method version;
- candidate examples where rights permit.

This lets the system learn from the program's real-world track record without making unsupported causal claims about a specific neurotransmitter or component.

If a historical statement such as “thousands of approvals” is to appear as a numeric product fact, attach an auditable source. Until then, retain it as reported practitioner-scale outcome history, not an invented database count.

## 9. Scientific correction must improve the method, not erase it

Examples from the recovered scientific pack:

- dopamine participates in learning, effort valuation, motivation/action and control but is not a single “gasoline” meter;
- “more dopamine” is not universally better and effects depend on circuit/task/baseline;
- sleep loss increases attentional effort cost and impairs performance; motivation does not fully replace sleep;
- habit automaticity develops gradually and variably; a single 21/30/66-day law is not justified;
- habitual behavior and reward are distributed across interacting systems rather than one simple circuit;
- regular physical activity may support health/cognition, but BDNF/dopamine mechanisms do not justify a universal pre-study dose;
- stimulant effects are heterogeneous and belong to clinical decision-making;
- supplement evidence is outside the core learning protocol.

Product translation:

> Keep the useful behavior. Remove only the unjustified biological certainty.

## 10. Canonical precedence when evidence conflicts

For product action:

1. safety / law / current official exam source;
2. verified target-exam facts;
3. observed candidate evidence;
4. strong direct learning evidence relevant to the intervention;
5. Batismo/Masterclass operational canon and documented outcome history;
6. indirect/mechanistic evidence;
7. course heuristic/example;
8. unsupported metaphor.

This is not a prestige ranking. It is a conflict-resolution rule for an adaptive system.
